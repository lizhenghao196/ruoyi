### 关键设计：菜单不存节点快照
轮询会整体重建 graph（`layoutFlow` 每次返回全新节点对象），存引用等于存一份永不更新的快照 —— 会出现「菜单写着暂停、节点其实已经成功」。
所以：`menuNode` 每次按 `flowKey + nodeId` 从最新 `flows` 里查 → `menuStatus`（字符串，起收敛作用，避免节点对象重建导致 `menuItems` 反复重算）→ `menuItems = buildNodeMenu(menuStatus, ...)`。
副产品：**轮询改了状态，已打开的菜单项会自己跟着变**，这是刻意保留的行为。
`watch menuNode`：节点被刷没了（流被替换 / plan 失败清空）→ 自动收起菜单。

## 执行页面 —— 静默时长 0 = 取消静默 + 弹窗按截图重做

### 0 的语义（关键）
**静默时长填 0 = 取消静默，不是「静默 0 分钟」**（截图里的温馨提示第二条就是这个意思）。
所以「0」在整条链路上都必须被当成「没配静默」：

- **读侧** `noticeDelayMinutes`：`n > 0` 才算有静默，`value: 0` 返回 `null` → 图标不显示。
- **写侧** `withNoticeDelay`：`delayMin <= 0`（或非法）时把 `noticeDelay` **整项从数组里移除**，
  不留 `{key:'noticeDelay', value:0}` 残渣 —— 否则后面读数据时看着像「还配着」。
- 双保险的意义：前端读侧把 0 当没配，后端**无论选择「写 0」还是「删项」**，节点上的图标都会消失。

## 17:20 澄清：`JSON.parse(JSON.stringify(x))` 的意图是深拷贝

用户指出我上一条的措辞不准确 —— 那行是**为了深拷贝、不改原对象**，不是写错了。我说「参考实现有 bug」

**我的 `readJson` 同样不污染原对象**：字符串输入 `JSON.parse` 得到新对象；对象输入只读不写、不碰原引用。

**改了两处**：
1. `planExecuteTime` 的注释改成「先承认意图（深拷贝/不动原对象），再说明字符串输入下的差异」——
