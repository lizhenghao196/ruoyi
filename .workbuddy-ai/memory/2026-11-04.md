## 系统画像：几百个集群的展开卡顿（先诊断后开方）

用户反馈生产上 310 集群的组件点「一键展开」很卡。先做只读性能测量（playwright + CDP Profiler），
注入 310 集群 / 1550 主机 / 170 链路，结论**反直觉**：

- 点击到绘制完成 3456ms，主线程阻塞 2289ms（单次长任务 1692ms）
- echarts 只占 3.4%（setOption 191ms），`buildTopology` 只有 7ms
- 真凶：`getTransitionInfo` 14.7% + `collapse-transition.enter` 14% + el-table `resizeListener` 10.9%
- 根因：`el-collapse` 内容用 `v-show`，310 个 el-table 首屏就全建好（70608 DOM 节点），
  展开时 310 个面板同时改 display → 310 次强制同步布局
- **CSS 禁 transition 无效**（3456→3364ms），Element 是 JS 内联 style 驱动

**已实施方案①**：`.el-collapse-item__wrap` 加 `content-visibility: auto` +
`contain-intrinsic-size: auto 320px` ⇒ **968ms（-72%）**，阻塞降到 864ms。
验证 12 项全过：屏外表格滚动到可见时正常渲染（5 行/宽 1041/内容对）、tableWidth 正常、
收起再展开无残留、控制台零报错；三个既有脚本（28/38/51 项）回归全过。

**未做（已记录在 REF §3.6）**：v-if 懒渲染、IntersectionObserver 视口挂载、分批展开、
echarts 大图降级（光点是「页面一直卡」的独立原因，170 边时静止 55fps）、el-table 换轻量表格。

## 系统画像：切到 310 集群的组件要等几秒（生产反馈）

用户上线 CV 版本后反馈：点组件拓扑切到 310 主机的组件，下侧要过几秒才出画面。
根因和「一键展开」同源 —— `el-collapse` 内容用 `v-show`，切组件时 310 个 el-table
（7 万 DOM 节点）全量销毁重建。

**改成三层懒加载**（`index.vue`）：
1. `isClusterOpen(name)`：只有展开的集群才建 `el-table`（`v-if`）
2. `isClusterMounted(name)` + `IntersectionObserver`（root = `.profile-hosts__panel`，
   rootMargin 400px）：展开但屏外先渲染占位块，滚到附近才建表
3. 保留 `content-visibility: auto`，`contain-intrinsic-size` 调成 300px 与占位高度对齐

⚠️ 两个坑：
- 加 v-if 后展开瞬间没有内容可量高度，`el-collapse` 的 max-height 过渡把表格压成 0
  ⇒ 必须 `.el-collapse-item__wrap { max-height: none !important }`
- `setOpenClusters` 里要把收起集群的挂载标记一起撤掉，否则再展开会瞬间重建全部表格

**实测**：切组件 几秒 → **118ms**（DOM 70608 → 3858）；一键展开 310 个 3456 → **1011ms**
（只建 3 个表格 / 307 个占位）；滚动 4500px 挂 18 个表，fps 44.8、单次最长任务 61ms。
验证：21 项 + 20 项（真实 mock 回归）+ 既有 28/38/51/34 项全过。
