## 追加修复：0 流环境过滤的判据用错了（loaded → responded）

用户反馈「还是显示 0 流的环境」，截图里 3 个环境全是 `0 流`、页头写着「0 个环境 · 0 条流 · **3 个环境获取失败**」。

**根因（两层）**：

1. **直接原因**：我把过滤判据写成了 `!e.loaded || e.flowCount > 0`。`loaded` 的语义是「有没有拿到数据」，
   而**请求失败时 `loaded` 也是 false** —— 于是失败的环境被那句「未加载时保留」的防御兜住了，漏出来显示成「0 流」。
   正确的判据是 **`responded`（请求有没有回来，成功失败都算）**，已在 `envList` 里补上 `responded: !!item`。
2. **根本原因（数据层）**：`mockData/res.js` 里 **`planRes` 有 31 个计划，`executeResMap` 只有 11 个 key —— 缺 20 个**。
   页面一（execPlanList）列的是 planRes，所以点进 BPC / DPS / PAY / DSI / LMP / DNET / CIS 这些系统时，
   3~4 个环境**全部取不到详情**（`getExecuteIndex` 直接 reject：`未找到执行详情：<id>`），
   页面上就是一堆「0 流」环境。截图那个系统正是其中之一（prod / failover / sandbox 三个环境）。

**修复**：`visibleEnvList` = `envList.filter(e => !e.responded || e.flowCount > 0)`。

- 首屏 `results` 还是空数组 ⇒ `responded` 为假 ⇒ 全部保留（不闪空）；
- 请求回来了（含失败）⇒ 只看 `flowCount`，取不到详情的环境同样隐藏；
- 失败环境数在页头「N 个环境获取失败」里有交代，信息不丢。

**空状态文案**顺带改准确：`envList.length ? "暂无有流的环境" : "未接收到环境"` ——
以前不会空，现在会空，写死「未接收到环境」是误导。

**验证**（node 复刻 envList / visibleEnvList 算法跑真实 mock 数据）：

| --- | --- |
| 首屏未响应（3 个 id，results 空） | 保留 3 个 ⇒ 不闪空 |
| BPC（截图场景，3 个环境全取不到详情） | visibleEnvList 为空 ⇒ 环境行不出 chip |
| AUTH（prod 6 流 / failover 3 流 / sandbox **真 0 流**） | 只显示前 2 个，sandbox 隐藏 |
| DASP（prod 2 流 / failover 1 流 / failover 2 流 / sandbox 0 流） | 显示 3 个，sandbox 隐藏 |
