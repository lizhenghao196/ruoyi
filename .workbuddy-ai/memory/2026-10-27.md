## 工单甘特图 · 「推送到企微」三字段的 Python 版（新增，纯增量）

用户要求：在不影响前端逻辑的前提下，把推送到企微用的 `date / peopleNum / detail` 三个数据的获取逻辑用 Python 重写一份，生成独立 py 文件，`date` 取当天。

新增 `py/order_workload.py`（仅此一个新文件，前端零改动，`git status` 只有 `?? py/`）：

- 逐函数移植 `ganttLayout.js`（`parse_time`/`start_of_day`/`build_day_window`/`normalize_mode`/`resolve_span`/`compute_node_timeline`）与 `workloadCalc.js`（`cost_intervals`/`overlap_minutes`/`calc_extra_staff`），外加 `build_payload` = 前端 `handleStaffPush` 里的 `{...staffResult, date}`。
- `date` 默认 `today_str()`；五段划分/除数(4、10)/阈值(2、1) 常量全部与前端同名同值。
- 只依赖标准库；`fetch_orders`（POST orderList，走 `_pick_payload` 的 data→rows 口径）、`push_to_wecom`、`--mock`（内置与前端 mock 一致的 8 条工单）、`--orders-file`、`--date`、`--push`。
- 两个易错点按前端教训处理：`js_round`（JS `Math.round` 的 .5 进位，不能用 Python 银行家舍入）；**不校验 code**（python 侧成功码是 0，判 `===200` 会误杀）—— 桩服务返回 `code:0` 已验证判成功。

验证（都在 Temp 里跑的临时脚本，未入库）：
- 与前端 JS 同数据对拍 **300 组随机用例 0 mismatch**（含 153 组 `peopleNum>0`，覆盖逻辑一/逻辑二；随机覆盖脏 mode、脏 beginTime、plan 在跨度外、node 乱序、total_cost 缺失）。做法：读两个 JS 源文件、剥掉 `import/export` 关键字后在同一个 `new Function` 作用域里执行，避开 ESM 扩展名解析问题。
- 桩服务验证 HTTP 往返 + 推送体就是 `{date, peopleNum, detail}` 三字段。
- 命令行错误分支（坏日期 / 接口不可达 / 文件不存在）统一输出一行人话 + exit 1，不打 traceback。
