# 2026-09-22

## 工单甘特图：柱体文字从白字换成同色系深色

**用户反馈**：「手动绿条上的文字看不清，文字是白色的；自动蓝条上也看不清」。

**定位（先量再改）**：柱体底色是「浅 → 中」的渐变（`--og-*-a` → `--og-*-b`），白字对比度低到不可读：

| 柱体 | 白字对比度 | 改后（深色字） |
| --- | --- | --- |
| 手动绿 `#a7f3d0 → #34d399` | 1.44 → 1.92 | `#065f46`：5.99 → 4.00 |
| 自动蓝 `#bfdbfe → #5b9cf8` | 1.58 → 2.32 | `#1e3a8a`：7.29 → 3.73 |

（`og_ink_check.mjs` 按 5% 步长沿渐变扫全区间算的 WCAG 对比度。）

**改动（只动 `components/OrderGantt.vue` 的 style 块，JS 一行没碰）**：
1. `.og` 里加 `--og-manual-ink: #065f46` / `--og-auto-ink: #1e3a8a`（跟已有的 `--og-*-a/b/soft` 同族命名）。
2. `.og-bar.is-manual/.is-auto` 各映射 `--og-bar-text: var(--og-*-ink)`；`.og-bar` 基类留 `--og-bar-text: var(--og-text-2)` 兜底。
3. `.og-bar__text` 的 `color` 从 `rgba(255,255,255,0.96)` → `var(--og-bar-text)`，**删掉 text-shadow**（那是给白字救场的，深字挂着会把边缘糊脏）。

**为什么选这两个色**：都取同色系 800/900 档，WCAG 相对亮度 0.087 / 0.051（差 0.035），
两组并排不会一边重一边轻；最差位置对比度 4.00 / 3.73，接近。

**踩到的坑**：
- 「两组文字明度接近」不能用 HSL 明度 `(max+min)/2` 判 —— 蓝色系 B 通道天生把它抬高，
  深蓝会被误判成比深绿轻（实测差 0.13 假失败）。改用 **WCAG 相对亮度**，差 0.035 通过。
- `og_scss.mjs` 里检测 `text-shadow` 要先剥注释：新写的注释里就含「text-shadow」这几个字，否则误报。

**顺手修掉的既有问题（与本次改动无关，纯属校验脚本自身的脆弱点）**：
`og_verify.mjs` §4 有两处**日期硬编码导致的假失败** —— `buildOrderList` 不传 `now` 时默认取 `Date.now()`，
而窗口断言用固定日期 `2026-09-21 15:23` 算，**隔一天就必然报「主窗口 0 条」**（改之前实测就是 0/100）。
修法：提出 `const OG_NOW = new Date(2026, 8, 21, 15, 23, 0)`，两处调用都注入。修完 `FAILURES: 0`。

**校验**：`og_scss.mjs` FAILURES:0（新增 6 条柱体文字断言）、`og_verify.mjs` FAILURES:0、`og_preview.mjs` 正常出图。
浏览器实测计算样式：手动 `rgb(6,95,70)`、自动 `rgb(30,58,138)`、`textShadow: none`，51/100 条柱体带文字。

**新增脚本**：
- `og_ink_check.mjs` —— 文字色候选的对比度体检（纯计算，改配色前先跑它选色）。
- `og_shot_ink.mjs` —— 开静态预览 HTML 截柱体文字（`deviceScaleFactor:2`）。
  ⚠️ 预览页 `.og__plotwrap` 实测只有 ~192px 高（`og_preview.mjs` 的 `DIALOG_VH` 模拟值偏小），
  AUTO 蓝条置底全被裁在视口外，截图前得先把滚动容器撑到 620px。

**产物**：`og-ink-overview.png`（绿条+蓝条同框）、`og-ink-auto.png`（蓝条特写）、`orderGantt-preview.html`。
