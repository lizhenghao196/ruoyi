## 追加：两级数量都不固定（用户反馈「告警源有十几二十个，AI处置里的字段也可能十几个」）

**问题**：上一版的 `NestedGroups` 一级用 `el-tabs`、二级用**单行** `el-radio-button` 分段按钮。
三五个时好看，十几二十个时会挤爆（tab 要靠箭头翻、分段按钮横向溢出）。

**改法**（`NestedGroups.vue` 重写 + `shape.js` 加两个纯函数）：
- 一级（处置结果）→ **左侧竖排导航** `aside.ng__nav`：色点 + 名称 + 条数，`width:212px`、
  `max-height:420px`（与表格 `max-height` 对齐）+ `overflow-y:auto`，十几个也不挤。长名字省略号收尾。
- 二级（告警源）→ **可换行的筛选 chip** `div.ng__chips`（`flex-wrap: wrap`），第一个是**「全部」**，
  chip 上带条数。二十个就是 2 行小 chip，不会溢出。
- ⚠️ **语义从「切换」改成「筛选」**：默认就是「全部」（不再默认只显示第一个告警源），
  这样任何告警源都不会被默认藏起来；表格里本来就有 `alertSource` 列，能看出每条属于哪个源。
- 新增 `shape.js` 纯函数：`ALL_GROUPS = '__all__'` / `levelRowCount(level)` / `flattenLevel(level, filter)`。
  `flattenLevel` 在**筛选值失效**（数据刷新后那个告警源没了）时**退回全部**，不给用户一张莫名其妙的空表。
  组件里 `activeFilter` computed 也做同样校验，保证「高亮的 chip」和「表格里的行」永远一致。
- 窄屏 `@media (max-width:1100px)`：`.ng` 改 `flex-direction: column`、导航 `width:100%; max-height:180px`。
- 每个一级**各自记自己的筛选值**（`activeGroup[一级名]`），切走再切回来还在；重新查询才整体复位。

## 追加二：`ng__nav` 高度拉满 + 表格底部 border 不显示（两个真 bug）

**用户原话**：「ng__nav 这个高度拉满吧，领导不喜欢有空余空间看着，还有，表格现在最下面的
border 没显示出来，看起来有点不完整，查一查咋回事，修复一下」

### 修 1：表格底部没有横线 —— 根因是 `.el-table::before` 被自己关掉了

- **根因**：`AlarmTable.vue` / `DuplicateTable.vue` 的 scoped 样式里各写了一句
  `::v-deep .el-table { &::before { display: none } }`。
- **为什么这一句是致命的**：Element 的 `.el-table--border { border-right: none; border-bottom: none }`
  **把根元素的下边框去掉了**，所以表格**底部那条横线完全靠 `.el-table::before`（1px 绝对定位）来画**
  （右侧竖线是 `.el-table--border::after`，与这条无关）。
- 行的 `td` 各自有 `border-bottom`，但表格是 `max-height` 滚动容器 —— 滚到中间时最后一条可见行的线
  **并不在容器底边**，所以容器底线必须由 `::before` 提供。
- **修法**：删掉那两句，原位留「不能写这个」的警告注释。

### 修 2：`ng__nav` 比右侧内容矮 20px —— 根因是全局 `aside` 元素选择器漏进 scoped 组件

- 已用「绝对定位列表 + `align-items:stretch`」让导航高度由右侧内容决定，但实测**恒定差 20px**
  （常规 `navH:436 / mainH:456`、压力 `navH:303 / mainH:323`）。
- **根因**：`ruoyi-ui/src/assets/styles/index.scss:99` 有一条**全局元素选择器**
  `aside { background:#eef1f6; padding:8px 24px; margin-bottom:20px; line-height:32px; font-size:16px; ... }`，
  命中了组件里的 `<aside class="ng__nav">`。
- ⚠️ **关键认知（这次最大的收获）**：**CSS 特异性只对「双方都声明过的属性」生效**。
  `.ng__nav[data-v-x]`（0,2,0）特异性虽然高于 `aside`（0,0,1），
  但**我没声明的属性照样吃全局值** —— 所以「特异性更高」并不等于「不会被污染」。
  `margin-bottom: 20px` 让 stretch 拉伸出的高度被扣掉 20px，正好就是那 20px。
- **修法**：在 `.ng__nav` 里把 `margin` / `padding` / `line-height` / `font-size` **一起显式归零**，并写清楚为什么。

### 像素断言的三个坑（都踩过，写进技能了）

1. **`page.screenshot({clip})` 报 `Clipped area is either empty or outside the resulting image`**
   → 目标元素在视口外。**截图前先 `el.scrollIntoView({ block: 'center' })`**。
2. **不能用严格 hex 相等比较两条线是不是同一色**：Chrome 截图带色彩配置转换，且线落在整数/半像素位置时
   抗锯齿混合程度不同 —— 同一条 `#ebeef5` 实测会读成 `#ebeef5` 或 `#e6ebf5`（±5 色阶）。
   → 改成「**已知边框色族 + 通道容差 10**」。
3. **`isLineGray` 判据太松会把页面背景当线**：初版写 `r<250 && g<250 && b<255`，
   页面背景 `#f5f7fa`（r=245）也被判成线 → P3 表格下方是页面背景，假红。
   → 改成 **`255 - min(r,g,b) >= 14`**（真边框至少比纯白暗 14 阶：`#ebeef5`→20 ✓、`#f5f7fa`→10 ✗）。
