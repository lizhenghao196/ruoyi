## 执行界面简版：右栏「文档信息」接入后端 HTML 文档（execPageSimple）

**背景**：后端 Flask 把渲染好的 HTML 落在 `rendered_docs/`，由
`cicd_bp` 的 `/doc/view/<filename>` 用 `send_file(file_path, mimetype='text/html')` 发出来。
用户问这个 URL 能不能嵌到简版右栏的「文档信息」区。

**结论**：能。关键点是 `send_file` 没传 `as_attachment=True`、也没传 `download_name`
⇒ Flask 不加 `Content-Disposition: attachment` ⇒ 浏览器原地渲染，iframe 同样渲染。
唯一真实风险是**全局 `X-Frame-Options`**（handler 里没设，但 after_request / talisman / nginx 可能加），
前端改不了，必须在服务器上确认。

**改动**（只动 `ruoyi-ui/src/views/tool/execPageSimple/index.vue` 一个文件）：
- 右栏由「纯占位」改为双态：有 `docUrl` → 工具栏（文件名 / 刷新 / 新窗口打开）+ iframe；
  没有 → 原占位空壳（不影响现有观感）。
- 新增 `docUrl` / `docName` 计算属性、`onDocFrameLoad` / `startDocFrameTimer` /
  `reloadDoc` / `openDocInNewTab` 方法、`docFrameKey` / `docFrameLoaded` / `docFrameTimer` 数据。
- 新常量 `DOC_FRAME_TIMEOUT_MS = 8000`：只用于「无条件收加载遮罩」，**不是**被拦的判据。
- 刷新靠换 `docFrameKey` 重建 iframe（src 不变浏览器不重发请求）。
- `beforeDestroy` 里清 `docFrameTimer`。
- 样式：`.esp-doc` 基座规则一字未动（保住 [H] 的 `flex: 4 1 0` / `min-width: 0` / 无 `width`），
  新增 `.esp-doc.is-filled` 修饰类 + `__bar` / `__name` / `__ops` / `__btn` / `__frame` / `__frame-mask`。

**数据来源暂时挂 URL**：`docUrl` 目前只认 `?docUrl=`（vue-router 已解码，**不要再 decodeURIComponent**）。
等接口给出文档地址字段后，把 `docUrl` 计算属性的取值换成接口字段即可，页面其余部分不用动。

**校验**：`esp_verify.mjs` 跑出 `FAILURES: 0`（含 [H] 6:4 分栏、[I] 圆点+自动滚动全部通过）。
另写了专用脚本 `esp_doc_verify.mjs`（Temp，51 条断言，四段：模板两态渲染 / 页面实例行为 /
SCSS 产物 / 源码防回归），也 `FAILURES: 0`。dev server 已在 10:39:47 热更新编译通过
（只有那个历史遗留的 `.zip` 警告，与本次无关）。

**写校验脚本时踩的两个坑（都是脚本的锅，不是页面的锅，已补进技能）**：
1. 页面里 `window.open` → node 必须桩 `globalThis.window`，否则报错指向临时产物文件；
2. 全局 `Vue.mixin` 会作用到**每一个**实例，**不能**靠「第二个实例再传 `beforeCreate`」覆盖
   （`Vue.mixin` 是全局的，实例自己的钩子顶不掉它），要让 mixin 读一个外层可切换变量。

**坑（写进注释了）**：
跨域 iframe 被 X-Frame-Options 拦掉时，**`load` 事件照样会触发**（加载的是空白错误页），
所以前端**无法**区分「加载成功」和「被拦」，别拿超时做断言 —— 真正能确认的只有控制台报错。

## 执行界面简版：文档区第四轮 —— 横向滚动（14:40~14:50）

**用户**：「如果页面比较宽，好像没有横向滚动条，没办法横拉去看，竖向滚动条是有的，怎么办」
（附图：iframe 里的节点明细表格列数多、被挤成竖条，右边看不到，没有横条可拉）

**根因**：`.esp-doc__frame` 是 `overflow: hidden` + `iframe { width: 100% }` ——
iframe 被压到容器宽（实测 **609px**），宽表格在文档内部就被挤/裁掉，
而**父页面这一层没有溢出**，所以父容器压根不会出横条。

**关键约束（决定了只能这么解）**：文档是**跨源**内网页（`10.2.64.36:8121`），
`contentDocument` / `contentWindow` 被同源策略挡死 ⇒ 读不出内容真实宽度、注入不了
`overflow-x: auto`、也没法把滚轮映射成横向滚动（事件在 iframe 内部就消化了，不冒泡）。
**唯一纯前端可行 = 撑大 iframe 的视口，让溢出落到父容器上。**

**落地**（`.esp-doc__frame`）：`overflow: hidden → auto` + 细滚动条（8px / `#cbd5e1`，
抄左栏 `.esp-flow__canvas`）+ `iframe { width: 100%; min-width: 1440px; height: 100% }`；
模板给滚动容器挂 `ref="docFrame"`，新增 `resetDocScroll()`（切 tab 后 `scrollLeft` 归零）。

- ⚠️ **`height: 100%` 解析的是扣掉横条后的内容盒**，所以横条出现后 iframe 不会多出 8px
  再顶出一条纵向滚动条 —— 浏览器实测 `scrollHeight == clientHeight == 773`，验证了这个推理。
- 最终形态：**横向滚动条在父容器、纵向滚动条仍在 iframe 内部**（不对称，但跨源下到头了）。
- 要「像纵向那样顺手」只能后端配合：① 加代理 + `DOC_VIEW_BASE` 换相对路径（同源）；
  ② 生成文档的模板自己给表格套 `overflow-x: auto`（治本）。**若某些文档在 1440 下仍被裁，
  只需调 `min-width` 这一个数。**

**校验**（三个脚本全 `FAILURES: 0`）：
- `esp_doc_verify.mjs` C 段新增 10 条：`overflow: auto` 且**不许**再有 `overflow: hidden`、
  `::-webkit-scrollbar(-thumb)`、`ref="docFrame"`、`resetDocScroll` 改的是 `$refs.docFrame.scrollLeft`、
  代码里不出现 `contentWindow`/`contentDocument`。
- `esp_doc_shot.mjs` 新增 [G] 段（真实浏览器量像素）：`overflowX === 'auto'`、
  iframe 实测 **1440px**、`scrollWidth 1440 > clientWidth 609`、`scrollLeft = 400` 真读回 400、
  `resetDocScroll()` 归零、视口自身无纵向溢出；再 `setViewportSize(2200)` 复查横条仍在。
  原 [G] 控制台段顺延成 [H]。

**两个校验脚本自身的坑**：
1. **sass 会把嵌套规则拍平成同级选择器** —— `.esp-doc__frame iframe` /
   `.esp-doc__frame::-webkit-scrollbar` 都**不在** `.esp-doc__frame { }` 那个块里，
   搜 `frameBlk` 必然假红，必须各自 `ruleBlock(noComment, '.esp-doc__frame iframe')` 取。
2. **判「代码里不读 iframe 内部」必须先剥注释** —— 那几处「跨源拿不到 contentWindow」的
   说明本身就写在注释里，直接搜 100% 假红。
