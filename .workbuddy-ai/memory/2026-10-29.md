## 系统画像：链路图改为「选中 key + 下游整条链」（需求）

**需求**：选组件拓扑里的一项，以它下面的 key 为根，在链路数据里找 fnode 为这些 key 的，**并且**这些节点的下游（孙子、曾孙……）连线也要画出来。原实现只做第一层 `fnode === 集群名`，MYSQL 只能看到 mysql→canal，后半条链断了。用户还提到生产上的现象：主机列表里没有某个集群、但链路里有它发出的线，页面上就整条不显示。

**改动**（纯展示层，接口/mock 数据一个字节没动）：
- `linkTopology.js / filterLinksByClusters`：改成**向前的传递闭包** —— 根名全等命中 → 建邻接表 → 迭代 BFS 展开下游 → 返回「起点在可达集合里」的链路。只向前不向上（选 MYSQL 不带 NGINX→MYSQL），环靠 `visited` 兜住。函数签名/名称不变，调用方无感。
- `index.vue` 新增两个 computed：
  - `relationNodeNames` = `集群关系[activeComponent].nodes`（去重 trim）—— 根节点的第二个来源，解决生产上「组件拓扑缺集群」漏链；
  - `linkRootNames` = `expandedClusters` ∪ `relationNodeNames`，但组件拓扑有集群且全收起时返回 `[]`（保住「全收起 ⇒ 无链路」）。
  `refreshTopo` 改传 `linkRootNames`；模板注释同步。

**效果**（mock 49 条全量）：MYSQL 4→13 条 / 13 节点 / 6 层（mysql→canal→kafka→es→gw），CANAL 3→9，GREATDB 3→12，应用 14→18，NGINX 3→3，测试仍 0（空态用例保住）。没有组件把全图吞掉。

**验证**：`Temp/sp_closure_check.mjs`（纯函数 30 项：三层链/环/上游边/空根/全等/trim）+ `Temp/sp_page_check.mjs`（抠 `index.vue` 的 `<script>` 在 node 里跑，19 项：MYSQL/CANAL 展开、全收起空态、生产场景「主机列表缺集群但集群关系有」仍能画）。dev server 热编译 `Compiled successfully`。
